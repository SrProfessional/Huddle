Getting started

Your first day, step by step

You do this once. It takes 20 to 40 minutes, mostly waiting for downloads. When a step depends on your computer, there is one block for Windows and another for Mac. Your project may add its own steps (its libraries, its test database): they are in the project's README and step 7 points you there.

Copy each command from its box, whole and on a single line. If it pastes split in two lines, join it before pressing Enter.

  1. Choose how you will use Claude Code

    Claude Code works the same in all its versions: the same rules, the same CLAUDE.md and the same Huddle plugin. Pick the one you find most comfortable; you can switch later.

    Desktop app · the easiest

    For people who are starting out. You see the changes visually and can have several sessions side by side. Requires a paid Claude plan.

    Install: follow the Windows or Mac download links at code.claude.com/docs/en/desktop-quickstart, sign in and open the Code tab.

    VS Code extension

    For people who want to read and edit the code in an editor while working with Claude Code.

    Install: VS Code from code.visualstudio.com; then open the extensions panel (Ctrl+Shift+X or Cmd+Shift+X), search for Claude Code (by Anthropic) and install it. The extension has no /plugin command: you install Huddle from a terminal in step 4.

    Terminal (CLI)

    For people who already use the command line. It is also the one that shows Huddle's notice the moment a session opens.

    Install: on Windows, in PowerShell:

    irm https://claude.ai/install.ps1 | iex

    On Mac, in Terminal:

    curl -fsSL https://claude.ai/install.sh | bash

    Then type claude inside the project folder.

  2. Install Git and your platform's command line

    Git keeps the code's history. Huddle talks to your platform through its official command line: gh for GitHub, glab for GitLab. Install the one your project uses.

    Windows
    1. Git: download «Git for Windows» from git-scm.com and install it with the default options. It includes Git Bash.
    2. GitHub: open PowerShell and type:
      winget install --id GitHub.cli
    3. GitLab:
      winget install --id GLab.GLab
    4. Close the terminal and open a new one, so it finds the new programs. In VS Code, close every window and open it again.
    Mac
    1. Git: open Terminal and type (two hyphens before install):
      xcode-select --install
    2. Homebrew (the Mac's program installer): follow the one-line instruction at brew.sh.
    3. GitHub:
      brew install gh
      GitLab:
      brew install glab

    Check: in a new terminal, gh --version (or glab --version) answers with a version number.

  3. Connect your accounts

    The repository: accept the invitation that arrives by email. Until you accept it, Huddle cannot assign you Issues.

    GitHub: type gh auth login and choose GitHub.com, HTTPS and «Login with a web browser».

    GitLab: type glab auth login, choose gitlab.com (or your company's server) and sign in with the browser. Then let Git use glab for gitlab.com, so a Claude Code session can push without opening a browser:

    git config --global --add credential.https://gitlab.com.helper "!glab auth git-credential"

    Claude Code: open it and sign in with the Claude account the AI Manager tells you.

  4. Install the Huddle plugin

    Huddle comes as a Claude Code plugin. Each person installs it once on their own computer; committing it to the repository does not install it for you. In a terminal:

    claude plugin marketplace add SrProfessional/Huddle
    claude plugin install huddle@huddle

    Then open a new Claude Code session. In the CLI you can also type /plugin marketplace add SrProfessional/Huddle and /plugin install huddle@huddle instead.

    Check: claude plugin list shows huddle@huddle enabled. To update it later, run claude plugin marketplace update huddle and open a new session.

  5. Set your language (a single message)

    Issues come in English, so Claude Code would answer in English unless you set your language. Open a session and send this message, replacing YOUR_LANGUAGE with your language written in English (for example spanish or portuguese):

    Add "language": "YOUR_LANGUAGE" to my personal Claude Code settings file, ~/.claude/settings.json. Keep everything else in that file as it is.

    It asks for permission to edit the file: accept it. From then on it answers in your language in every session. Commits, PRs and comments stay in English.

  6. Download the project and open it

    In a terminal, go to the folder where you keep your projects and clone it (the AI Manager gives you its name):

    gh repo clone OWNER/PROJECT

    On GitLab: glab repo clone OWNER/PROJECT. Then open that folder in the Claude Code you chose. When it asks whether you trust the folder, say yes.

  7. Do your project's own setup

    Every project has its own libraries and tests. Open its README (and its CLAUDE.md) and follow the setup section, or ask Claude Code: «read the README and install what the project needs, then run the tests and tell me the results».

  8. Check that Huddle sees everything

    Ask Claude Code: «run huddle doctor». Every line must show ✔: plugin, huddle.json, login, ai_manager and labels. If one shows ✖, its line says what to do (for login: «not installed or not on the PATH» means gh or glab is missing from this terminal, and the line gives the install command; «not logged in» means run gh auth login or glab auth login); if it is not clear, send it to the AI Manager.

  9. Take your first Issue

    Find the Issue assigned to you (label assigned), or type gh issue list --assignee @me. In Claude Code type:

    /huddle-start N

    with the Issue's number instead of N. It checks that the Issue's dependencies are merged, creates your branch in a folder of its own, marks the Issue in progress and starts the Issue's prompt. Answer its questions calmly: that is where your work is.

  10. When the AI Manager asks for changes

    You do not need to watch GitHub. After its closing message the session keeps waiting for the review. When the AI Manager leaves a request, the session tells you and asks whether to continue: say yes. If you had closed Claude Code, open a new session in the project: Huddle tells you that a request is waiting (in the CLI you see the line at once; in the desktop app and the VS Code panel Claude says it after your first message).
