Get started with Huddle

Install the plugin, set up one repo, write the first Issue. Then a Player takes it. About five minutes for the setup, thirty for a Player's first day.

1. Install the plugin

Every Player installs Huddle once, on their own machine. A settings file committed to the repo does not do it for them. You need:

  • Claude Code↗ (opens in a new tab) or OpenAI Codex↗ (opens in a new tab) (its command line or its VS Code extension). Each person picks their own, and the Coach and the Players may mix them.
  • Node 22 or newer, and git.
  • On GitHub, the gh↗ (opens in a new tab) command line, logged in with gh auth login. On GitLab, the glab↗ (opens in a new tab) command line, logged in with glab auth login (add --hostname gitlab.example.com for a self-managed server).

In Claude Code

Run this once in any terminal, then open a new Claude Code session:

claude plugin marketplace add SrProfessional/Huddle
claude plugin install huddle@huddle

In the Claude Code command line you can type the same as /plugin marketplace add SrProfessional/Huddle and /plugin install huddle@huddle. The VS Code extension uses /plugins instead of /plugin: type /plugins, add the marketplace SrProfessional/Huddle in the Marketplaces tab, install huddle from the Plugins tab with Install for this project (not «Install for you»), and type /reload-plugins (or restart Claude Code). Each person does this once per clone. Huddle has no runtime dependencies, so there is nothing to npm install.

To update later. Install and update are per project, so repeat this in each project that uses Huddle. From the project, type one command:

/huddle-update

It updates the plugin (claude plugin marketplace update huddle and claude plugin update huddle@huddle --scope project), refreshes the templates and the CLAUDE.md block in a branch of its own, asks only the questions a new release added, and opens the PR. It ends by telling you to type /reload-plugins; if the new skills do not show up, restart Claude Code. A project can be on an older version than another. /huddle-play and /huddle-update tell you in the chat when a newer release exists, at most once a day.

In OpenAI Codex

On macOS, follow the Mac setup steps.

The same marketplace, the same skills and the same huddle command. Run this once in a terminal (the VS Code extension of Codex brings its own codex; the team guide says how to find it if codex is not recognized):

codex plugin marketplace add SrProfessional/Huddle
codex plugin add huddle@huddle

In a repo already set up with Huddle, the file .codex/config.toml declares Huddle for Codex: trust the project when Codex asks, and run codex plugin marketplace upgrade huddle once in a terminal in the repo instead. Then, once per machine:

  1. Trust the hook in terminal Codex. The Codex chat in VS Code has no /hooks, so open a terminal in the repo, start codex --no-daemon, choose Review hooks (or type /hooks), and trust Huddle's row under SessionStart. Then type /exit.
  2. Allow network access. Codex's sandbox has no network: approve it when Codex asks to run git push, gh, glab or huddle.
  3. Open a new chat. Codex has no /reload-plugins. In Codex the skills start with $: $huddle-play <n>, $huddle-watch and so on. huddle doctor shows a «codex» line.

To update in Codex: codex plugin marketplace upgrade huddle, then codex plugin add huddle@huddle, then a new chat (and trust the hook again if it changed). Only design work still needs Claude Code. The team guide↗ (opens in a new tab) has every step, with the hook trust walkthrough. Adapted but not yet tried live in Codex: $huddle-bug, $huddle-areas, $huddle-team, playing several Issues in parallel, and GitLab.

Set up Huddle on a Mac with Codex

Codex on macOS is adapted for Huddle but not yet tried live.

  1. 🙋 Install Homebrew. If you need it, follow the installation and Next steps at Homebrew↗ (opens in a new tab). Homebrew installs tools on your Mac.

    You should see: The installer finishes and tells you how to make brew available in Terminal (the app where you paste commands).
    If you see something else: Follow the installer's instructions before continuing.

  2. 🙋 Install the tools. Open Terminal from Applications → Utilities, then paste this command. 
    brew install node gh git

    You should see: Homebrew installs Node (which runs Huddle), GitHub CLI (which signs you in to GitHub from Terminal) and Git (which copies and tracks your project files), or reports that they are already installed.
    If you see something else: If brew is missing, complete Homebrew's Next steps and open Terminal again.

  3. 🙋 Sign in to GitHub. In Terminal, paste the following. Choose GitHub.com, HTTPS, and Login with a web browser when prompted. 
    gh auth login

    You should see: GitHub CLI confirms that you are logged in.
    If you see something else: Complete the browser prompt and return to Terminal.

  4. 🙋 Install the Codex command. In Terminal, paste this command. The global install adds codex to your PATH (where new terminals look for commands). 
    npm install -g @openai/codex

    You should see: npm reports that it added or updated Codex.
    If you see something else: If a new Terminal window cannot find codex, check that Homebrew's Next steps were applied.

  5. 🙋 Sign in to the Codex extension. In VS Code, open Extensions, search for Codex, install the extension published by OpenAI and sign in.

    You should see: The Codex sidebar opens with your account signed in.
    If you see something else: Choose Sign in in the sidebar and finish in your browser.

  6. 🙋 Clone your repo. In Terminal, copy the repo (your team's project) to this Mac. The example copies Huddle to the Huddle folder in your home folder. For your own repo, replace SrProfessional/Huddle with the name from GitHub and Huddle in the destination with your project folder name. 
    gh repo clone SrProfessional/Huddle "$HOME/Huddle"

    You should see: Git reports that it is cloning into your project folder.
    If you see something else: For an access error, check the repo name and the account you signed in with.

  7. 🙋 Open a terminal in the repo. In VS Code, choose File → Open Folder, select the folder you just cloned, then choose Terminal → New Terminal.

    You should see: The new terminal opens in the repo folder.
    If you see something else: Check that you opened the folder created by the clone command.

  8. 🙋 Trust the project folder. Start terminal Codex and approve the project trust prompt for your repo if it appears. Sign in if prompted. Close the chat with /exit before running the next terminal command. 
    codex --no-daemon

    You should see: Codex opens the repo without a warning that its project settings are ignored.
    If you see something else: Reopen terminal Codex from the repo folder and review the trust prompt.

  9. 🙋 Add the Huddle marketplace if needed. If the repo has no .codex/config.toml and you haven't already added the marketplace, paste this in the repo terminal. The marketplace tells Codex where to find Huddle. 
    codex plugin marketplace add SrProfessional/Huddle

    You should see: Codex reports that it added the marketplace.
    If you see something else: If it is already configured, continue to the next step.

  10. 🙋 Refresh the marketplace. In the repo terminal, paste this command. 
    codex plugin marketplace upgrade huddle

    You should see: Codex refreshes the Huddle marketplace.
    If you see something else: If Codex cannot find it, check folder trust and whether the repo has .codex/config.toml, or complete the previous step.

  11. 🙋 Install Huddle. In the repo terminal, paste this command. 
    codex plugin add huddle@huddle

    You should see: Codex reports that it added Huddle.
    If you see something else: If it cannot find Huddle, repeat the marketplace refresh.

  12. 🙋 Open terminal Codex. In the repo terminal, paste this command before reviewing the hook (a command that runs when a chat starts). 
    codex --no-daemon

    You should see: Codex opens in the repo and may say Hooks need review.
    If you see something else: If it cannot find the command, reopen the terminal after installing the Codex command.

  13. 🙋 Trust Huddle's startup hook. In terminal Codex, type this command. Select SessionStart, open Huddle's row, confirm that it runs node "${CLAUDE_PLUGIN_ROOT}/bin/huddle" hook for the huddle plugin, and choose Trust. 
    /hooks

    You should see: SessionStart shows the Huddle hook as active.
    If you see something else: If the Huddle row is missing, check that you started Codex in the repo after installing Huddle.

  14. 🙋 Leave terminal Codex. Press Esc to return to the chat, then type this command. 
    /exit

    You should see: You are back at the terminal prompt.
    If you see something else: If the hook list is still open, press Esc again first.

  15. 🙋 Set your personal language if the team has none. Run the following in the terminal for Spanish. Change es to your own language code if needed. 
    node ~/.codex/plugins/cache/huddle/huddle/*/bin/huddle language es

    You should see: Huddle confirms your language.
    If you see something else: If several versions are installed, replace * with the installed version you want to use.

  16. 🙋 Start a new Codex chat. In the repo, open a new Codex chat in VS Code or terminal Codex.

    You should see: Huddle introduces itself when the chat starts.
    If you see something else: If it does not, review the Huddle hook again in terminal Codex.

There is one watch per repo per machine. Huddle keeps its watch marks in ~/.huddle on that machine. If you use two computers as Coach, keep the watch on one at a time. Run $huddle-watch off in Codex (or /huddle-watch off in Claude Code) on the first computer before starting the watch on the other. Players may work on both computers.

2. Set up your repo

This is the Coach's step, once per repo. Open Claude Code or Codex in the repo and create a branch for the setup:

git switch -c huddle-setup
  1. Run /huddle-setup ($huddle-setup in Codex). It asks for the platform (GitHub or GitLab), the host (empty for github.com or gitlab.com), the project, the login of the Coach and the logins of the Players.
  2. It also asks whether the project has a staging branch where changes are tested first (staging_branch); answer none if not.
  3. It writes huddle.json, the Issue and pull request templates, the Huddle block of CLAUDE.md and AGENTS.md (which Codex reads), and .codex/config.toml. There is no cloud job: the sessions keep the labels right. Nothing outside the Huddle blocks and tables is touched.
  4. Run huddle doctor. You want a check mark on the file, the login, the Coach and the labels. If a label is missing, run huddle labels once.
  5. Commit, push and open a pull request with the setup files. Merge it. The Coach is the only one who merges.

On GitLab the steps are the same, with nothing extra to set up. With a staging branch, Issue branches start from it and their pull requests target it; the Coach closes the Issue with huddle land, marks it tested there with huddle tested, and runs /huddle-release to take staging to the default branch once everything in it was tested. The GitLab notes↗ (opens in a new tab) cover self-managed servers.

3. Write the first Issue

Run /huddle-issue ($huddle-issue in Codex). It writes the Issue from the template, so every task arrives complete:

PartWhat it says
GoalWhat we want to achieve and why, in a few lines.
Prompt for Claude CodeThe text the Player pastes, with the steps, the branch and how to open the pull request.
Allowed filesThe only files the session may touch.
Forbidden filesWhat is not touched. If it must be, the session asks first.
Contract or specThe document that rules over the code.
TestsWhat must pass before the pull request opens.

4. A Player's first day

  1. Set up your machine. Install Claude Code or Codex, Node, git and gh or glab, log in yourself, and install Huddle with the commands above for your tool. Never paste a token into a chat, a file or an Issue.
  2. Check it works. Clone the team's repo, open Claude Code or Codex in it and run huddle doctor. If labels fails, tell the Coach: only they run huddle labels.
  3. Take an Issue. The Coach's session assigns one when it is ready. Run /huddle-play <n> ($huddle-play <n> in Codex) with its number, or paste the Issue's prompt. The session checks what the Issue depends on, creates its own branch and adds the in progress label. If a dependency is not merged yet, it stops, and that is right.
  4. Answer its questions. The session chats with you in your language from the first message (set your own once with huddle language es); the repo stays in English. This is the job. If you do not know, say so and let the session ask the Coach.
  5. Review what it did before you accept the pull request. You are responsible for it.

A session ends with a message that starts with «Issue #N finished» or «Issue #N stopped», with the pull request link, the test counts, what was not done and your next step. After the pull request opens, the session waits in the background and picks up the Coach's requested changes on its own. The waiting is a small Node process on the Player's computer that asks GitHub or GitLab every two minutes: it uses no Claude tokens and no GitHub Actions or CI minutes. In Codex the same wait (huddle wait <n> --codex) wakes the open chat when the Coach answers. On the other side, the Coach can run /huddle-watch ($huddle-watch in Codex) to let their session review what waits. There is one watch per repo on a machine, whatever the tool: a second session says where the watch already runs and does not start another. With /huddle-play alone, the session works on several of the Player's assigned Issues at once, as many as their capacity allows.
