Decision-led development for teams coding with AI

Huddle is a Claude Code plugin for teams. One person hands out the tasks, every developer's AI session does one, and the people spend their time deciding and reviewing instead of typing.

Every task shows where it is

An Issue moves along five stops. Labels on the Issue say where it is, and they update on their own. Two side roads exist because the AI is allowed to stop and ask.

Details of every label: how it works.

Five developers, five Claude Code sessions

AI tools made writing code cheap. They did not make a team faster on their own. When each person prompts the AI in their own way, each session understands the project differently, and the trouble shows up late, in review or in production.

  • Who does whatEvery task has its own Issue, its own branch and its own files, so two people do not collide.
  • Who decidesWhen a session meets a choice that is not its to make, it stops and asks the AI Manager, with options and a recommendation.
  • Nothing is droppedEverything an Issue asks for ends up done, or written down as not done, with the reason.

How it works in four steps

  1. The AI Manager writes Issues

    Each task comes with the exact prompt to paste, the files it may touch and the tests that must pass.

  2. Each developer's session takes one

    The session reads the Issue, checks what it depends on, and works on its own branch.

  3. A pull request with tests

    First the failing test, then the code. The pull request lists the tests it ran, with real counts.

  4. The AI Manager reviews and merges

    They answer the questions, ask for changes or merge. Only they merge, and only they touch production.

GitHub and GitLab

Huddle works on github.com and on GitHub Enterprise Server, and on gitlab.com and on a company's own GitLab server. The commands are the same everywhere. Huddle uses the login of gh or glab and never reads or stores a token.

GitHub

A workflow keeps the labels up to date whenever an Issue or a pull request changes.

GitLab

A scheduled pipeline updates the labels every ten minutes. The AI Manager sets up the schedule and one token, once.

Install it in two commands

Every developer installs the plugin once, on their own machine. You need Claude Code, Node 22 or newer, git, and gh or glab. Run these in a terminal, then open a new Claude Code session:

claude plugin marketplace add SrProfessional/Huddle
claude plugin install huddle@huddle

Then, in your repo, the AI Manager runs /huddle-setup. The get started guide has every step. Huddle has no runtime dependencies and nothing to npm install.

Questions people ask

What is Huddle?

A team method and a Claude Code plugin. One person, the AI Manager, hands out tasks as Issues. Each developer's Claude Code session works on one task in its own branch, asks when a decision is not its to make, and opens a pull request for review.

How do teams use Claude Code together?

By giving every session the same context and the same rules. The Issue holds the goal, the allowed files and the tests, and the repo's CLAUDE.md holds the rules, so sessions started by different people behave the same way.

Does it work with GitLab?

Yes. It works with GitHub and GitLab, including a self-managed GitLab server. On GitLab the labels update on a pipeline schedule instead of reacting at once.

What does decision-led development mean?

The AI writes, tests and asks. The person decides. Our job is no longer typing code but making good decisions, and a session that cannot go on without one stops and asks instead of guessing.

Does Huddle need a server, an account or a token?

No server and no account. It runs on your machine with Node and the GitHub or GitLab command line you already log in to. The only token is a GitLab CI variable the AI Manager sets up for the label job.

Is it free?

Yes. Huddle is open source under the MIT license, and it has no dependencies and no trackers.
